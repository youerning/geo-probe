# Contributing to GEO Probe

Thanks for helping. This project is a static Next.js app with no backend; most logic lives in `lib/` and runs in the browser.

## Setup

```bash
pnpm install
pnpm dev
```

Node.js 20+ and pnpm 10+ are recommended.

## Before you start

- Read [`CONTEXT.md`](CONTEXT.md). Use its vocabulary in code, UI copy, and issues.
- Read the ADRs in [`docs/adr`](docs/adr) before changing storage, the provider pipeline, or the source/citation model.
- **Never commit an API key, `.env`, or exported data containing personal information.**

## Scripts

```bash
pnpm dev             # Next.js dev server
pnpm build           # static export to out/
pnpm lint            # ESLint
pnpm typecheck       # TypeScript
pnpm test            # Vitest
pnpm demo:generate   # regenerate public/demo/demo-data.json (needs DEEPSEEK_API_KEY)
```

## Project layout

```text
app/                 pages (static export; detail views use query params)
components/          UI, charts, drawers, dialogs
lib/analysis/        mention matching, source normalization, metrics
lib/providers/       provider adapter (DeepSeek today)
lib/db/              Dexie schema and repositories
lib/export/          JSON / CSV / Markdown
lib/demo/            demo seed
scripts/             demo data generation
examples/            optional Cloudflare Worker proxy
```

## Adding a provider

Providers must return a normalized result:

- final answer text
- search queries with result counts
- raw sources: title, URL, page age, query, rank
- token usage and latency

Then the shared analysis layer computes mentions, domains, channels, and metrics. Keep provider-specific parsing inside `lib/providers/`; don't fork the analytics.

Capability differences (e.g. whether the provider exposes source URLs) belong in the adapter and should be documented in the README/limitations.

## Tests

- Add unit tests for new analysis logic in `lib/analysis/*.test.ts`.
- Prefer small, deterministic fixtures over live API calls.
- Do not add tests that require a real API key.

## Pull requests

- Keep PRs focused; one concern per PR.
- Run `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build` before opening.
- Update `README.md` / `CONTEXT.md` / ADRs when behavior or vocabulary changes.
- Include screenshots for UI changes.
- Don't include secrets or personal data in fixtures, screenshots, or demo data.

## Demo data

`public/demo/demo-data.json` is generated by `pnpm demo:generate`. Before committing a regenerated file:

- Check answers and sources for phone numbers, emails, ID numbers, legal representatives, or other personal data.
- Keep the demo brand/competitor labels appropriate for a public repository.
- Mention in the PR what changed and why.
